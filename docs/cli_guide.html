HPC-AI AIMCR artifact management

commands

dashboard list
List artifacts. Filter by --status, --aimcr, --type. Add --json for machine-readable output.
dashboard inspect
Show full detail for one artifact — paths, checksums, curation notes, modification log.
dashboard move
Confirm move to gpup. Sets status=moved, partition=gpu, records timestamp and username.
dashboard block
Block with a required reason. Curator sees the reason in the dashboard.
dashboard reinstate
Reinstate a blocked or rejected artifact back to staged.
dashboard edit
Edit mover-owned fields: moving_notes, checksum_verified_gpup, destination_path, project_id.

chain of events

dashboard list / inspect
Read-only — queries the SQLite database, no files touched.
dashboard move
Validates gpup checksum, then runs the full move sequence.
YML updated on disk DB row synced modlog appended manifest synced
dashboard block / reinstate
Appends reason to moving_status_reason, changes status, propagates to modlog.
YML updated on disk DB row synced modlog appended manifest synced
dashboard edit
Loads YML, applies field changes, computes diff, writes everything back.
YML updated on disk DB row synced diff logged (old → new) manifest synced
UI reflects changes
Any user who refreshes the dashboard sees the updated status, fields, and modlog immediately.

HPC Ticket-driven transfers

commands

dashboard hpc list
List transfers. Filter by --status, --ticket. Add --json for machine-readable output.
dashboard hpc inspect <id>
Show full detail for one transfer — paths, verification counts, audit log, YML modlog.
dashboard hpc new
Create a new transfer record. Required: --ticket, --name, --src, --dst, --requester.
dashboard hpc premove <id>
Generate and write generate_checksum.slurm to workspace. Updates status → pre-move. Prints the sbatch command.
dashboard hpc postmove <id>
Generate and write verify_checksum.slurm to workspace. Updates status → verifying. Prints the sbatch command.
dashboard hpc verify <id>
Parse verify_result.txt, record pass/fail counts, update status → completed or anomaly. Use --result to override path.
dashboard hpc edit <id>
Edit transfer fields. Shows sync warning if edited field affects an already-generated script.
dashboard hpc block <id>
Block with a required reason.
dashboard hpc reinstate <id>
Reinstate a blocked transfer back to pending.
dashboard hpc status <id>
Manually set any status — useful for in-progress or correcting state.

chain of events

dashboard hpc list / inspect
Read-only — queries transfers.db and reads workspace YML modlog.
dashboard hpc new
Creates DB record, provisions workspace, writes initial artifact.yml and first modlog entry.
DB record created workspace provisioned artifact.yml written modlog entry appended
dashboard hpc premove
Writes generate_checksum.slurm to workspace. Updates status and YML. Prints the sbatch command — submission is your responsibility.
generate_checksum.slurm written status → pre-move YML updated modlog appended
dashboard hpc postmove
Writes verify_checksum.slurm to workspace. Updates status and YML. Prints the sbatch command.
verify_checksum.slurm written status → verifying YML updated modlog appended
dashboard hpc verify
Reads verify_result.txt, counts OK/FAILED lines, records counts in DB, updates status and YML.
counts + status → completed/anomaly YML updated modlog appended
dashboard hpc edit
Updates DB fields and mirrors changes into artifact.yml. Shows sync warning if changed field affects an already-generated script.
DB fields updated YML mirrored diff logged (old → new)
UI reflects changes
Any user who refreshes the HPC Transfer page sees the updated status, fields, and logs immediately.

demo — full hpc transfer workflow

step 1 — create the transfer record
dashboard hpc new \
  --ticket RT-12345 \
  --name imagenet-val \
  --src /scratch/project/k03/support_team/65638/datasets/imagenet-val \
  --dst /scratch/project/k00456/datasets/imagenet-val \
  --requester pi_user \
  --type dataset \
  --size 142.5

✓ Transfer created (ID: 7)
  workspace: /scratch/project/k03/support_team/workspace/RT-12345_imagenet-val
  run: dashboard hpc premove 7
step 2 — generate and submit checksum script
dashboard hpc premove 7

✓ Pre-move script written to: /scratch/project/k03/support_team/workspace/RT-12345_imagenet-val/generate_checksum.slurm

! Submission is your responsibility:
  sbatch /scratch/project/k03/support_team/workspace/RT-12345_imagenet-val/generate_checksum.slurm

# submit and wait for completion
sbatch /scratch/project/k03/support_team/workspace/RT-12345_imagenet-val/generate_checksum.slurm
squeue --me
step 3 — move the data
rsync -avP \
  /scratch/project/k03/support_team/65638/datasets/imagenet-val/ \
  /scratch/project/k00456/datasets/imagenet-val/
step 4 — generate and submit verify script
dashboard hpc postmove 7

✓ Post-move script written to: /scratch/project/k03/support_team/workspace/RT-12345_imagenet-val/verify_checksum.slurm
  result will be written to: .../workspace/RT-12345_imagenet-val/verify_result.txt
  then run: dashboard hpc verify 7

sbatch /scratch/project/k03/support_team/workspace/RT-12345_imagenet-val/verify_checksum.slurm
squeue --me
step 5 — import verification result
dashboard hpc verify 7

  total  : 8431
  passed : 8431
  failed : 0

✓ 8431/8431 files OK — marked completed.
anomaly — fix and re-verify
dashboard hpc verify 7

  total  : 8431
  passed : 8429
  failed : 2

✗ 2/8431 files FAILED — marked anomaly.
  review: .../workspace/RT-12345_imagenet-val/verify_result.txt

# re-rsync failed files and re-verify
grep "FAILED" .../verify_result.txt
rsync -avP /source/failed_file /destination/
sbatch .../verify_checksum.slurm
dashboard hpc verify 7
Sync warning on edit — if you edit source_path, destination_path, ticket_number, or artifact_name after scripts have been generated, the CLI prints a warning and tells you which script to regenerate. The record is still saved — the warning is informational, not a blocker.
