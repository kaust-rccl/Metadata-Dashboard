The dashboard CLI

A terminal interface for data movers. Confirm moves, update fields, and manage artifact status — all from the command line. Changes appear in the UI on next refresh.

setup

# add to ~/.bashrc so dashboard is available from anywhere
echo 'export PATH="/scratch/project/k03/support_team/Metadata_Dashboard/cli:$PATH"' >> ~/.bashrc
source ~/.bashrc

# verify
dashboard --help

commands

dashboard list
List artifacts. Filter by --status, --aimcr, --type. Add --json for machine-readable output.
dashboard inspect
Show full detail for one artifact — paths, checksums, curation notes, modification log.
dashboard move
Confirm the move to gpup. Sets status=moved, partition=gpu, records timestamp and username.
dashboard block
Block an artifact with a required reason. Curator sees the reason in the dashboard.
dashboard reinstate
Reinstate a blocked or rejected artifact back to staged.
dashboard edit
Edit mover-owned fields: moving_notes, checksum_verified_gpup, destination_path, project_id.

chain of events — what happens on each command

dashboard list / inspect
Read-only. Queries the SQLite database — no files are touched.
dashboard move
Validates gpup checksum is filled, then runs the full move sequence.
YML updated on disk DB row synced modlog entry appended manifest synced
dashboard block / reinstate
Appends a reason entry to moving_status_reason, changes status, propagates reason to modlog.
YML updated on disk DB row synced modlog entry appended manifest synced
dashboard edit
Loads current YML, applies field changes, computes a diff, writes everything back.
YML updated on disk DB row synced diff logged (old → new) manifest synced
UI reflects changes
The dashboard reads from the database. Any curator or browser who refreshes their page sees the updated status, fields, and modlog immediately.

demo — full mover workflow

step 1 — find what needs moving
dashboard list --status staged

  ARTIFACT                                 TYPE       STATUS     AIMCR
  ──────────────────────────────────────── ────────── ────────── ────────
  Seed-X-PPO-7B                           model      STAGED     65616
  LLaVA-Video-178K                        dataset    STAGED     65638
step 2 — inspect before moving
dashboard inspect 65616 Seed-X-PPO-7B

  Seed-X-PPO-7B
  STAGED  model

  ── curation ─────────────────────────────────────
  source path              /scratch/project/k03/support_team/65616/models/Seed-X-PPO-7B
  destination path         /scratch/project/k#####
  size (GB)                14.0
  cpup verified            True by x_mohameta
step 3 — fill in destination and project id
# curator left the destination as placeholder — fill it in
dashboard edit 65616 Seed-X-PPO-7B \
  destination_path="/scratch/project/k00123/models/Seed-X-PPO-7B" \
  project_id="k00123"

✓ Moving fields updated. Changes: destination_path: '/scratch/project/k#####' → '/scratch/project/k00123/models/Seed-X-PPO-7B'; project_id: 'k#####' → 'k00123'
step 4 — transfer the artifact outside the dashboard
# run the actual file transfer — outside the dashboard
rsync -avP \
  /scratch/project/k03/support_team/65616/models/Seed-X-PPO-7B/ \
  /scratch/project/k00123/models/Seed-X-PPO-7B/

# verify checksum at destination
cd /scratch/project/k00123/models/Seed-X-PPO-7B/
sha256sum -c checksum.sha256
# all files must show: OK
step 5 — confirm the move in the dashboard
dashboard move 65616 Seed-X-PPO-7B \
  --verified-by mover_username \
  --notes "transferred and verified on gpup"

✓ Artifact 'Seed-X-PPO-7B' moved successfully.
  verified by: mover_username
  notes: transferred and verified on gpup
  changes visible in the UI on next refresh
UI sync — after dashboard move, any curator or browser who refreshes the dashboard will see Seed-X-PPO-7B with status MOVED, the gpup checksum verification, and a full modlog showing the complete history from staging to move.

adjusting destination path and project id

Curators sometimes stage an artifact before the exact destination is confirmed, leaving k##### as a placeholder. Movers who know the correct project allocation fill these in before confirming the move.

update destination path only
dashboard edit 65616 Seed-X-PPO-7B \
  destination_path="/scratch/project/k00123/models/Seed-X-PPO-7B"
update project id only
dashboard edit 65616 Seed-X-PPO-7B project_id="k00123"
update both at once
dashboard edit 65616 Seed-X-PPO-7B \
  destination_path="/scratch/project/k00123/models/Seed-X-PPO-7B" \
  project_id="k00123"
Every edit is logged. The modification log records the old value, the new value, your username, and a timestamp. Curators and browsers can see the full change history in the dashboard under Modification log.
Other editable fields via CLI: moving_notes and checksum_verified_gpup. Everything else is owned by the curator and is read-only for movers.

handling problems

block — quota exceeded, bad checksum, path unavailable
dashboard block 65616 Seed-X-PPO-7B "quota exceeded on gpup — waiting for allocation"

✓ Artifact blocked: quota exceeded on gpup — waiting for allocation
  curator will see this reason in the dashboard
reinstate — once the issue is resolved
dashboard reinstate 65616 Seed-X-PPO-7B "quota resolved, destination confirmed"

✓ Artifact reinstated to staged.
  clearing reason: quota resolved, destination confirmed
  status is now: staged
correct a mistake after move confirmation
# wrong notes were entered — fix them after the fact
dashboard edit 65616 Seed-X-PPO-7B moving_notes="verified sha256 on gpup 2026-06-21"

✓ Moving fields updated. Changes: moving_notes: '' → 'verified sha256 on gpup 2026-06-21'

quick reference

# list
dashboard list
dashboard list --status staged
dashboard list --aimcr 65616
dashboard list --json

# inspect
dashboard inspect <aimcr> <name>
dashboard inspect 65616 Seed-X-PPO-7B
dashboard inspect 65616 Seed-X-PPO-7B --json

# move
dashboard move <aimcr> <name> [--verified-by USER] [--notes TEXT]
dashboard move 65616 Seed-X-PPO-7B --verified-by mover1 --notes "ok"

# block / reinstate
dashboard block <aimcr> <name> "<reason>"
dashboard reinstate <aimcr> <name> "<reason>"

# edit mover fields
dashboard edit <aimcr> <name> field=value [field=value ...]
dashboard edit 65616 Seed-X-PPO-7B destination_path="/scratch/project/k00123/models/Seed-X-PPO-7B"
dashboard edit 65616 Seed-X-PPO-7B project_id="k00123"
dashboard edit 65616 Seed-X-PPO-7B moving_notes="re-verified after network drop"
